## 1. 组件版本选择

### 问题
用户需要简单的方式在稳定版和最新版的工具链组件之间选择。

### 分析
- **LLDB 和 .NET Runtime**：已处理。配置项提供 tarball（固定）vs git（最新）选择。
- **binutils、gcc、gdb**：这些是 Buildroot 的内置包，其版本选择不在 4dotnet 中。
- **Linux 内核**：通过 defconfig 中的配置项设置版本。

### 决策：多个 defconfig 预设
```
savedconfigs/arm64/
├── br2.defconfig           # 默认：稳定工具链，LLDB=git/main，.NET=git/main
├── br2.defconfig.latest    # 全部最新
└── br2.defconfig.stable     # 全部固定到已知良好版本
```

## 2. 向全栈添加组件

### 提议添加
- **U-Boot 引导管理器**：真实的引导流程，内核命令行控制
- **GDB SOS 插件**：仓库 `https://github.com/oldzhu/gdbsos`，完善 GDB 端的调试体验
- **.NET 诊断工具**：dotnet-trace、dotnet-counters、dotnet-dump
- **性能分析工具**：perf + FlameGraph

## 3. AI/Agent 集成策略

### 决策：Skills + Memories（路径 B）
使用 OpenCode 的 skills/memories 架构，而非构建自定义 agent。

**架构**：
```
.opencode/
├── skills/          # 技能：构建、调试、发布、错误修复、教学
├── memories/        # 记忆：项目知识、已知问题、构建日志、版本兼容性
└── agents/          # 可选：专用构建器 persona
```

**自进化机制**：每个用户的 agent 独立进化，积累构建经验和解决方案。

---

## 4. 分发模式：从"下载镜像"到"构建 + Agent"

### 决策：混合模式
- **路径 A**（即用）：从 GitHub Releases 下载预构建镜像
- **路径 B**（学习/自定义）：git clone → agent 引导构建 → 自进化
